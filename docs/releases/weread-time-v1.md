# 微信读书时长同步 v1

2026-10-08，`doubaobaba/crossmux` fork 正式发布，标签 `weread-time-v1`。

离线阅读后，在当前书籍中点击 **同步进度**，即可同步阅读位置和本机记录的阅读时长。无需保持联网阅读，也无需等待与阅读时长相同的时间。

## 本版功能

- 新阅读时长按真实小时保存在 SD 卡，手动同步时批量上传，每批最多 16 个小时桶；“按小时保存”不表示必须等一小时才能同步。
- 同步前检查时长登录凭证。没有有效凭证时，在 X3 上显示二维码；微信扫码确认后保存凭证并继续同步。凭证独立保存在 SD 卡，不包含在固件中。
- 核对服务端书籍累计时长后确认批次；保留待同步和结果不确定的状态，避免不明确的请求自动重复上传。
- 修复登录响应解析、证书链兼容和原生同步阶段内存占用问题；TLS 连接成功后才将待同步记录转入发送状态。
- 只在手动同步期间联网，结果页关闭 Wi-Fi，没有新增后台定时联网。

## 下载与安装

[GitHub Release 下载页](https://github.com/doubaobaba/crossmux/releases/tag/weread-time-v1)

本次将已验证的 test8 固件原样发布；设备“关于”仍显示 **`1.6.0-time-test8`**。已安装该版本的设备无需再次刷机。

1. 备份 SD 卡，包含隐藏的 `.crosspoint` 文件夹。
2. 下载 `update.bin` 并核对 `SHA256SUMS.txt`，复制到 SD 卡根目录。
3. 在已有可用 CrossMux 的 X3 上使用原有 SD 卡更新流程。保留书籍、登录文件和时长账本。
4. 打开微信读书缓存的 EPUB，正常翻页阅读后点击“同步进度”；如出现二维码，使用书架所属的同一个账号扫码确认。
5. 在微信读书中刷新统计，核对实际入账。再次点击同步但没有新增阅读时，不应重复增加时长。

这是 ESP32-C3 X3/X4 共用应用镜像，实机反馈来自 X3；不是 S3 固件，也不是首次安装所需的完整刷机包。发布文件不含个人凭证或阅读记录。

## 已知限制

- 本地“阅读统计”和上传账本口径不同。当前代码在后台章节分页尚未结束时暂停上传计时，即使已有可读页面，也可能漏计。本版保留该行为，尚未修复或验证具体漏计量。
- 五分钟没有手动翻页等已接入的阅读交互会耗尽计时额度；自动翻页不会重置该额度。菜单、子页面和休眠不属于上传计时范围。
- “结果不确定”表示无法确认本次是否入账，并不代表确定未上传。此类批次不会自动重传，也不会自动恢复重试资格。不要把本地总时长直接补成上传时长。
- 仅同步当前书籍，每本最多保存 64 个待同步小时桶；超出容量或没有可靠日期的时间保留为未上报时间。时区固定为 Asia/Shanghai。
- 服务端允许回补历史记录的完整期限尚未确认，不能保证任意历史时长都可入账。第三方接口未来可能变化。
- X3 基本扫码和同步流程已有用户实机验证；长时间计时准确率、电池续航、其他设备及全部跨日场景不属于本次完整验收结论。
